# Dossier de contrôle PC-8 — Tranche 8 : reconnexion par SMS et « Mes billets »

27/10/2026 · Arrêt prévu : sécurité de l'accès aux billets, et premier vrai SMS par la passerelle Android (envoi vers l'extérieur, payant).

## 1. Ce qui est prêt
- **Connexion par code** (maquettes B6 et M1) :
  - numéro, puis code à 6 chiffres reçu par SMS, valable 5 minutes ;
  - renvoi possible après 60 secondes ;
  - code faux : « Il vous reste N essais » ; après 5 essais faux, « Trop d'essais », réessayer dans 15 minutes ;
  - numéro hors +235 refusé ;
  - la session ouverte par le code dure 90 jours sur ce téléphone.
- **Mes billets** (maquette B7), par la page `/mes-billets` ou le lien « Retrouver mes billets » au pied de chaque événement :
  - billets « À venir » et « Passés » ;
  - un bouton « Télécharger le billet N » par billet et « Voir » qui ouvre la commande ;
  - événement annulé : bandeau et bouton « Contacter le support » ;
  - événement reporté : bandeau « Reporté · Date à confirmer », billets toujours téléchargeables ;
  - billet annulé : bandeau ;
  - écran vide « Aucun billet pour ce numéro » ;
  - « Me déconnecter ».
- **Vérification du numéro avant la première réservation** (journal de bord n° 71) :
  - à l'achat, l'écran du code apparaît si ce téléphone n'a pas encore prouvé le numéro ; la réservation continue ensuite toute seule ;
  - les achats suivants depuis ce téléphone ne demandent plus rien ;
  - le champ « Confirmez votre numéro » disparaît, car le code prouve déjà le numéro.
- **Coupure de la vérification** : avec `BUYER_PHONE_VERIFICATION=off` dans `.env`, on revient à la double saisie si les SMS n'arrivent plus.
- **Email (n° 73)** : un achat sans email envoie quand même le billet à l'adresse déjà confirmée du compte, si ce numéro a été vérifié. Une adresse n'est rattachée au compte que par une commande passée avec le numéro prouvé.
- **SMS** : en développement, le SMS s'affiche dans le terminal de l'API. La passerelle Android est prête mais inactive tant que `.env` ne la renseigne pas (voir D10).

## 2. Comment le valider
### A. Sans vrai SMS (environ 15 minutes, ordinateur ou téléphone par le tunnel)
0. **Relancer les deux serveurs**, car la configuration et le site ont changé : Ctrl+C puis `pnpm dev:api`, et Ctrl+C puis `pnpm start:web`. Les migrations sont déjà appliquées à la base de développement.
1. **Première réservation** (fenêtre de navigation privée) :
   - Page d'un événement → « Choisir mes billets » : vérifier que le champ « Confirmez votre numéro » a disparu.
   - Remplir, puis « Payer » : l'écran « Entrez le code » s'affiche.
   - Le code est dans le terminal de l'API, sur la ligne `SMS (console, non envoyé) pour +235••••56 : Gatio : votre code est 481 902…`. Le saisir : la réservation continue vers le paiement (faux opérateur).
2. **Deuxième achat dans la même fenêtre** : aucun code n'est demandé.
3. **Mes billets** : au pied de la page de l'événement, « Retrouver mes billets » affiche vos billets.
   - Télécharger un billet.
   - « Voir » ouvre la commande avec ses QR codes.
4. **Erreurs du code** : « Me déconnecter », puis redemander un code et taper 5 codes faux. Attendu : « Il vous reste 4 essais »… puis « Trop d'essais ».
5. **Numéro sans achat** : se connecter avec un autre numéro jamais utilisé. Attendu : « Aucun billet pour ce numéro ».
6. **Email** :
   - Faire un achat avec un email, puis cliquer « confirmez votre adresse » dans http://localhost:8025.
   - Faire un achat suivant **sans** email depuis le même téléphone : le billet arrive quand même à cette adresse.
7. *(Facultatif)* Mettre `BUYER_PHONE_VERIFICATION=off` dans `.env` et relancer l'API et le site : la double saisie revient.

### B. Premier vrai SMS (seulement après votre accord, D10)
1. Sur un téléphone Android avec une carte SIM, installer l'application libre **SMS Gateway for Android** (code : github.com/capcom6/android-sms-gateway).
2. L'ouvrir et activer le **serveur local**. Elle affiche une adresse (`http://192.168.x.x:8080`), un identifiant et un mot de passe. Le téléphone et l'ordinateur doivent être sur le même Wi-Fi.
3. Dans `.env` (jamais dans `.env.example`) :
   - `SMS_GATEWAY_URL=http://192.168.x.x:8080/message`
   - `SMS_GATEWAY_LOGIN=…`
   - `SMS_GATEWAY_PASSWORD=…`

   Relancer ensuite l'API : le terminal affiche « SMS envoyés pour de vrai par la passerelle Android ».
4. Sur « Mes billets », demander un code avec **votre** numéro : le SMS arrive en quelques secondes, avec le texte de la maquette M1.
5. Après l'essai, vider `SMS_GATEWAY_URL` dans `.env` et relancer l'API : les SMS reviennent dans la console.
