# Tranche 2 — Compte organisateur et mot de passe oublié

## Contexte
Réponses du responsable (22/10/2026) : Q2 → champ « Nom affiché » ajouté à l'inscription (modèle inchangé) ; argon2 approuvé (0.45.1, script d'installation autorisé pour lui seul). Registre relu (ERR-001 à 005). Dette D2 (adresse IP derrière le relais) à traiter ici.

## Micro-plan
1. Base (Drizzle) : `users`, `organizers`, `auth_sessions`, `password_resets`, `rate_limit_counters`, types `user_role` et `account_status` ; migration.
2. API : hachage argon2id, jetons 256 bits hachés SHA-256, sessions (cookie `HttpOnly`, `SameSite=Lax`, `Secure` hors développement, ou en-tête `Authorization`), compteurs de limites atomiques en base, contrôle de l'origine sur les requêtes qui modifient (S2), `trustProxy` limité à 127.0.0.1 (D2).
3. Routes : `POST /auth/register`, `/auth/login`, `/auth/logout`, `/auth/password/forgot`, `/auth/password/reset`, `GET/PUT /organizer/profile`.
4. Port Email : adaptateur Mailpit (API HTTP de Mailpit, sans dépendance) et adaptateur de test en mémoire ; envoi par tâche pg-boss avec reprises ; email E3.
5. Web : pages O1 (inscription, connexion, mot de passe oublié, demande envoyée, nouveau mot de passe, succès, lien expiré) ; page d'accueil connectée provisoire.
6. Tests d'intégration sur vraie base : parcours complet, isolation, réponse identique pour un email inconnu, limites, jeton expiré ou réutilisé, sessions fermées après réinitialisation.

- Connexion réservée au rôle organisateur jusqu'à la tranche 14 (double authentification des comptes internes).
- Après inscription, la session est ouverte directement.
- Après connexion, page provisoire (aucune maquette « Mes événements » avant la tranche 3) : logo, nom affiché, lien « Me déconnecter » (texte repris de B7).
